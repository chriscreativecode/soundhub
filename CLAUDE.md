## Architecture

**sound-manager-ts** is a Web Audio API library, distributed as an npm package. The build produces ES module and UMD outputs alongside `.d.ts` declarations (via vite-plugin-dts).

### Build modes (vite.config.ts)

Vite is configured with three named modes:
- `lib` — builds the library to `dist/` (ES + UMD)
- `demo-main` — builds the interactive demo to `dist/demo/main/`
- `documentation-dev` — builds the docs site to `dist/documentation/`

`npm run build` runs all three sequentially. The `@` alias maps to `./src`.

### Core library (`src/sound-manager/`)

The entire public surface is one class: **`SoundManager`** (`sound-manager.ts`), which implements `SoundManagerInterface`. Everything else in `src/sound-manager/` supports it:

| File | Role |
|---|---|
| `sound-manager.interface.ts` | Public API contract (the source of truth for what is exposed) |
| `sound-manager-config.ts` | Default configuration values and their types |
| `sound-events.enum.ts` | 26+ event types used by the event system |
| `audio-node-connector.ts` | Builds and rewires the Web Audio node graph per-sound |
| `ticker.ts` | `requestAnimationFrame`-based callback scheduler (default 50 ms) |
| `sound-group.ts` | Groups of sounds for collective control |
| `sound-pan-type.enum.ts` | `STEREO` vs `SPATIAL` panning modes |
| `sound-panner-config.ts` | Spatial (3D) panner configuration |

`src/index.ts` re-exports everything that forms the public API.

### Audio pipeline

Each loaded sound goes through this node graph (assembled by `AudioNodeConnector`):

```
Source (AudioBufferSourceNode / HTMLAudioElement)
  → GainNode (per-sound volume)
  → StereoPannerNode  OR  PannerNode (depends on pan type)
  → GainNode (master volume)
  → AudioContext.destination
```

Panning type is set per-sound and can switch between stereo (`StereoPannerNode`) and spatial (`PannerNode` with HRTF or EqualPower). Spatial position is tracked via a `ConstantSourceNode`.

### Instance model

A single registered sound can be played as multiple simultaneous instances (`createNewInstance`). `SoundManager` tracks all live instances internally; each has its own node graph and state (playing / paused / stopped).

### Configuration

`SoundManagerConfig` (defined in `sound-manager-config.ts`) covers:
- Audio loading: preferred engine (Web Audio vs HTML5 fallback), parallel load limit, size cap
- Playback defaults: volume, rate, panning type
- Spatial audio: panning model, cone settings, rolloff
- Mobile: auto-unlock on user gesture, auto-mute on page hide, auto-resume on focus
- Network: fetch retries, timeout, CORS mode

### Demo (`src/demo/`)

The demo is self-contained and not part of the library output. Key entry point is `src/demo/pages/main/demo.ts` (the `Demo` class). UI components live under `src/demo/components/` — `SoundControl`, `MasterControl`, and `SpatialGrid` (a canvas-based 3D audio visualizer).

### Documentation (`src/documentation/`)

The docs site is a static HTML page generated by injecting the README.md (processed with markdown-it + highlight.js) into `template.html`. Run `npm run generate-docs` to regenerate after editing the README.
